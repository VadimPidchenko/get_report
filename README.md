# Get Report

**Get Report** — локальное веб-приложение для подготовки и генерации отчётов по проектам.

Приложение позволяет создавать и редактировать отчёты, добавлять изображения, формировать итоговые документы в форматах DOCX и PDF и сохранять историю работы локально на компьютере.

---

## Возможности

- создание и редактирование отчётов;
- добавление изображений;
- автоматическое формирование DOCX;
- автоматическое формирование PDF;
- локальное сохранение истории работы;
- работа через веб-интерфейс;
- запуск приложения через Docker.

---

# Установка и запуск

Get Report распространяется в виде готового Docker-образа.

В папке приложения находятся только файлы, необходимые для запуска Get Report и локального хранения пользовательских данных:

```text
get_report/
├── compose.yaml
├── README.md
├── drafts/
├── images/
└── reports/
```

Исходный код приложения для работы не требуется.

Само приложение находится в готовом Docker-образе:

```text
ghcr.io/vadimpidchenko/get_report:latest
```

При первом запуске Docker автоматически скачает этот образ из GitHub Container Registry и запустит приложение.

Папки `drafts`, `images` и `reports` используются для хранения пользовательских данных, поэтому во время обычной работы с приложением удалять их не нужно.

---

## 1. Установите Docker

Для работы Get Report требуется **Docker** с поддержкой **Docker Compose**.

Если Docker уже установлен, этот шаг можно пропустить.

Для обычного пользователя самый простой вариант — установить **Docker Desktop**. Установите его способом, рекомендованным Docker для вашей операционной системы.

Если вы раньше не устанавливали Docker, используйте официальную инструкцию Docker для своей операционной системы. При необходимости можно также воспользоваться поиском или попросить ИИ пошагово объяснить установку Docker Desktop именно для вашей ОС.

После установки откройте терминал и выполните:

```bash
docker --version
docker compose version
```

При успешной установке обе команды должны вывести информацию о версиях Docker и Docker Compose, например:

```text
Docker version 28.x.x, build ...
Docker Compose version v2.x.x
```

Номера версий могут отличаться — это нормально. Важно, чтобы обе команды выполнялись без ошибок и показывали установленную версию.

Если это так, Docker готов к работе.

---

## 2. Запустите приложение

Перед запуском убедитесь, что Docker запущен. Если вы используете Docker Desktop, сначала откройте его и дождитесь запуска Docker Engine (в левом нижнем углу будет подсвечена надпись Engine running).

Откройте терминал в папке `get_report`, где находится файл `compose.yaml`, и выполните:

```bash
docker compose up -d
```

Эта команда запускает Get Report в фоновом режиме.

При первом запуске Docker ещё не имеет образа Get Report на компьютере, поэтому автоматически скачает:

```text
ghcr.io/vadimpidchenko/get_report:latest
```

из GitHub Container Registry.

Поэтому первый запуск может занять немного больше времени, чем последующие. При обычных следующих запусках Docker будет использовать уже скачанный локальный образ.

После успешного запуска откройте в браузере:

```text
http://localhost:8000
```

Get Report готов к работе.

# Обновление приложения

Новые версии Get Report публикуются в GitHub Container Registry.

Когда становится доступно обновление приложения, выполните:

```bash
docker compose up -d --pull always
```

Docker проверит актуальную версию образа в GitHub Container Registry.

Если опубликована новая версия, Docker скачает необходимые изменения и запустит Get Report на обновлённом образе.

Ваши черновики, изображения и созданные отчёты при обновлении сохраняются.

Для обычного запуска использовать `--pull always` не требуется. В остальных случаях достаточно:

```bash
docker compose up -d
```

---

# Остановка приложения

Чтобы остановить Get Report, выполните:

```bash
docker compose down
```

Команда остановит и удалит контейнер приложения, но не удалит пользовательские данные.

Для следующего запуска снова выполните:

```bash
docker compose up -d
```

---

# Где хранятся данные

Все пользовательские данные Get Report хранятся **локально на вашем компьютере** в папке приложения:

```text
drafts/    — сохранённые черновики отчётов
images/    — загруженные изображения
reports/   — сформированные отчёты DOCX и PDF
```

Эти каталоги подключаются к Docker-контейнеру, но физически остаются на компьютере пользователя.

Поэтому остановка или пересоздание контейнера не удаляет историю работы.

Например, после:

```bash
docker compose down
```

файлы в `drafts`, `images` и `reports` останутся на месте.

Чтобы полностью удалить историю работы, необходимо вручную удалить соответствующие файлы из этих каталогов или через веб-интерфейс, выбрав нужный отчет, нажать "удалить".

# Jira

По умолчанию в поле **«Таск-трекер»** в шапке приложения используется базовый адрес Jira:

```text
https://jira.a7-tech.local/browse/
```

Для сотрудников A7 дополнительная настройка обычно не требуется.

Приложение формирует ссылки на задачи на основе указанного базового адреса.

В поле **«Задачи»** у тест-кейсов и баг-репортов можно указать только номер задачи, например:

```text
A7RU-111
```

В итоговом отчёте будет отображаться введённый номер задачи со ссылкой на Jira.

Ссылка формируется из базового адреса в поле **«Таск-трекер»** и указанного номера задачи.

Также в поле **«Задачи»** можно вставить полный URL. В таком случае указанный URL будет использован как есть, а базовый адрес из поля **«Таск-трекер»** учитываться не будет.

Если используется другая Jira или другой таск-трекер, базовый адрес можно изменить непосредственно в приложении.

# Основные команды

Запуск приложения:

```bash
docker compose up -d
```

Обновление образа и запуск приложения:

```bash
docker compose up -d --pull always
```

Остановка приложения:

```bash
docker compose down
```

Проверка состояния контейнера:

```bash
docker compose ps
```

Просмотр логов:

```bash
docker compose logs -f
```

Для выхода из просмотра логов нажмите:

```text
Ctrl + C
```

Это прекращает только просмотр логов и не останавливает само приложение.

# Возможные проблемы

## Порт 8000 уже занят

Если при запуске появляется ошибка, связанная с портом `8000`, значит этот порт уже используется другим приложением.

Остановите приложение, использующее порт `8000`, и повторите:

```bash
docker compose up -d
```

---

## Docker установлен, но приложение не запускается

Если при выполнении:

```bash
docker compose up -d
```

появляется ошибка наподобие:

```text
unable to get image 'ghcr.io/vadimpidchenko/get_report:latest': failed to connect to the docker API at unix:
```

или сообщение о том, что Docker daemon / Docker Engine не запущен, скорее всего Docker установлен, но в данный момент не работает.

С большой вероятностью, вы просто забыли запустить Docker перед выполнением команды. 
Убедитесь, что вы открыли Docker Desktop и в левом нижнем углу подсвечена надпись Engine running.

После этого снова выполните:

```bash
docker compose up -d
```

---

## Docker не запускается

Проверьте, что Docker установлен и доступен:

```bash
docker --version
docker compose version
```

Если используется Docker Desktop, убедитесь, что он запущен и Docker Engine работает.

---

## Не скачивается образ приложения

При первом запуске Docker должен скачать образ:

```text
ghcr.io/vadimpidchenko/get_report:latest
```

Для этого требуется подключение к интернету и доступ к GitHub Container Registry.

Иногда при обращении к GHCR может возникнуть временная сетевая ошибка, например:

```text
failed to fetch anonymous token
context deadline exceeded
```

В таком случае откройте новый терминал в папке `get_report` и повторите:

```bash
docker compose up -d
```

Если ошибка возникает постоянно, проверьте интернет-соединение и доступ к:

```text
ghcr.io
```

---

## Приложение запущено, но страница не открывается

Проверьте состояние контейнера:

```bash
docker compose ps
```

Затем посмотрите логи:

```bash
docker compose logs -f
```

Если приложение успешно запущено, оно должно быть доступно по адресу:

```text
http://localhost:8000
```

---

## Не создаётся PDF

При запуске Get Report через Docker все необходимые компоненты для формирования PDF уже находятся внутри Docker-образа.

Если PDF не создаётся, посмотрите логи приложения:

```bash
docker compose logs -f
```
