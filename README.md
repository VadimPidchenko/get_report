# Get Report

Локальное веб-приложение для подготовки и генерации отчётов по проектам.

Приложение позволяет создавать отчёты, добавлять изображения, формировать итоговые документы в форматах DOCX и PDF и сохранять историю работы локально.

Проект в первую очередь предназначен для подготовки отчётов по проектам A7, но при необходимости может использоваться и отдельно.

---

## Возможности

- создание и редактирование отчётов;
- добавление изображений;
- автоматическое формирование DOCX;
- автоматическое формирование PDF;
- сохранение истории локально;
- повторное открытие ранее созданных черновиков;
- работа через простой веб-интерфейс;
- запуск через Docker или напрямую через Python.

---

# Рекомендуемый способ запуска — Docker

Это самый простой вариант для обычного использования приложения.

Не нужно отдельно устанавливать Python, Node.js, npm, LibreOffice и зависимости проекта — готовый Docker-образ публикуется в GitHub Container Registry (GHCR).

## 1. Установите Docker

Установите Docker Desktop или Docker Engine с Docker Compose.

Проверить установку можно командами:

```bash
docker --version
docker compose version
```

---

## 2. Скачайте проект

### Вариант 1 — через Git

```bash
git clone https://github.com/VadimPidchenko/get_report.git
cd get_report
```

Если Git не установлен, проект можно скачать с GitHub как ZIP:

**Code → Download ZIP**

После скачивания распакуйте архив и откройте терминал в папке проекта.

---

## 3. Запустите приложение

```bash
docker compose up -d
```

Docker Compose использует опубликованный образ:

```text
ghcr.io/vadimpidchenko/get_report:latest
```

Если образ ещё не скачан на компьютер, Docker загрузит его автоматически из GitHub Container Registry и затем запустит контейнер.

После успешного запуска приложение будет доступно по адресу:

```text
http://localhost:8000
```

Откройте этот адрес в браузере.

---

## Обновление Docker-версии приложения

Чтобы перед запуском проверить наличие новой версии образа и при необходимости скачать её, используйте:

```bash
docker compose up -d --pull always
```

Параметр `--pull always` заставляет Docker Compose перед запуском проверить актуальный образ в GHCR.

Если образ не изменился, уже имеющиеся слои будут переиспользованы.

Если опубликована новая версия, Docker скачает недостающие слои и пересоздаст контейнер на актуальном образе.

---

## Просмотр логов

```bash
docker compose logs -f
```

---

## Остановка приложения

```bash
docker compose down
```

Команда останавливает и удаляет контейнер, но не удаляет ваши черновики, изображения и созданные отчёты.

# Где хранятся данные

Все пользовательские данные сохраняются непосредственно в папке проекта на вашем компьютере.

```text
drafts/    — черновики отчётов
images/    — загруженные изображения
reports/   — сгенерированные отчёты в DOCX и PDF
```

Эти папки подключаются к Docker-контейнеру с хоста.

Поэтому после:

```bash
docker compose down
```

данные сохраняются.

Чтобы полностью удалить историю работы, необходимо вручную удалить содержимое соответствующих каталогов.

# Запуск без Docker

Этот вариант в первую очередь предназначен для разработки.

Для запуска потребуется:

- Python 3.12;
- Node.js;
- npm;
- LibreOffice;
- Git — если проект скачивается через `git clone`.

---

## 1. Скачайте проект

```bash
git clone https://github.com/VadimPidchenko/get_report.git
cd get_report
```

---

## 2. Создайте виртуальное окружение Python

```bash
python3 -m venv .venv
```

### Linux / macOS

```bash
source .venv/bin/activate
```

### Windows PowerShell

```powershell
.venv\Scripts\Activate.ps1
```

---

## 3. Установите Python-зависимости

```bash
pip install -r requirements.txt
```

---

## 4. Установите Node.js-зависимости

```bash
cd generator
npm ci
cd ..
```

---

## 5. Установите LibreOffice

LibreOffice используется для преобразования сформированного DOCX в PDF.

Установите LibreOffice средствами вашей операционной системы.

Без LibreOffice приложение сможет работать, но генерация PDF может быть недоступна.

---

## 6. Запустите приложение

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

После запуска откройте:

```text
http://localhost:8000
```

# Jira

По умолчанию в поле **«Таск-трекер»** в шапке приложения используется базовый адрес Jira:

```text
https://jira.a7-tech.local/browse/
```

Для сотрудников A7 дополнительная настройка обычно не требуется.

Приложение формирует ссылки на задачи на основе указанного базового адреса.

В поле **«Задачи»** у тест-кейсов и баг-репортов можно указать только номер задачи, например:

```text
A7RU-111
```

В итоговом отчёте будет отображаться введённый номер задачи со ссылкой на Jira. Ссылка формируется из базового адреса в поле **«Таск-трекер»** и указанного номера задачи.

Также в поле **«Задачи»** можно вставить полный URL. В таком случае он будет использован как есть, а базовый адрес из поля **«Таск-трекер»** учитываться не будет.

Если используется другая Jira или другой таск-трекер, базовый адрес можно изменить в приложении или в конфигурации проекта.

# Возможные проблемы

## Порт 8000 уже занят

Если при запуске появляется ошибка, связанная с портом `8000`, значит его уже использует другое приложение.

Остановите приложение, использующее порт, и повторите запуск.

---

## Docker не запускается

Проверьте:

```bash
docker --version
docker compose version
```

Также убедитесь, что Docker Desktop или Docker Engine запущен.

---

## Ошибка при скачивании образа из GHCR

Иногда при первом скачивании публичного образа может появиться ошибка наподобие:

```text
failed to fetch anonymous token
context deadline exceeded
```

Это может быть временной сетевой ошибкой при обращении к GitHub Container Registry.

В таком случае повторите команду:

```bash
docker compose up -d
```

или:

```bash
docker compose up -d --pull always
```

Если ошибка повторяется постоянно, проверьте интернет-соединение и доступ к `ghcr.io`.

Для публичного образа дополнительный GitHub-токен не требуется.

---

## Приложение работает, но страница не открывается

Проверьте логи:

```bash
docker compose logs -f
```

И убедитесь, что приложение доступно по адресу:

```text
http://localhost:8000
```

---

## Не создаётся PDF

Для прямого запуска без Docker убедитесь, что LibreOffice установлен и доступен из командной строки.

При запуске через Docker LibreOffice уже входит в опубликованный образ.
